# 010 自动化

自动化是按时间表自动开始的任务，比如"每个工作日 18:30 汇总本周 GitHub 热榜，报告保存到桌面"。前置阅读：[003 运行时](003-runtime.md)、[007 连接器](007-connectors.md)（另一种"工作的来源"）。

## 是什么

一条自动化 = 要做的事 + 时间表 + 和手动任务一样的选项（工作文件夹、保存到、模型、联网）。

- **到点就开始一个普通任务：** 标题是自动化的名称，触发来源是 `automation`。任务走同样的沙箱、独立工作区、审批和通知。
- **自动化只负责"什么时候、做什么"：** 结果就在那个任务里，和你手动发起的任务一样查看、追问、保存、删除。
- **删除自动化时：** 它开始过的任务都保留。

## 时间表

`packages/protocol/src/automation.ts` 定义了三种：

| 类型 | 例子 | 说明 |
|---|---|---|
| `daily` | 每天 09:00 | 本机时区，跨夏令时也按墙上时间 |
| `weekly` | 工作日 18:30、每周一三 09:00 | `days` 中 0 是周日 |
| `interval` | 每 6 小时 | 从上一次运行算起 |

到期的计算在 `packages/core/src/schedule.ts`。它是纯函数，用本地时间构造的日期做测试，所以在任何时区都成立：

- `nextRun(schedule, after)`：严格晚于 `after` 的下一个时间点。
- `dueRun(schedule, since, now)`：`(since, now]` 区间里**最后一个**到期时间点。

## 运行规则

`apps/daemon/src/runtime/automations.ts` 的 `AutomationRunner`：每 30 秒检查一次，守护进程启动时也检查一次。

- **从哪里算起：** 取上一次运行的时间和 anchor 中较晚的一个。anchor 是创建时间；改了时间表或者重新启用，就更新为当时的时间。所以修改不会立刻补跑已经过去的时间点。
- **错过的只补一次：** 电脑休眠或守护进程没开的那几天，醒来后只运行最近到期的那一次，不会把每天都补一遍。
- **不叠跑：** 上一次运行的任务还没结束，这次就跳过，并记下原因（"上一次还在运行"）。手动"立即运行"遇到这种情况会直接报错。
- **不会重复：** 创建任务和记录这次运行在同一个 SQLite 事务里，任务的触发编号是 `<自动化 id>@<计划时间>`。崩溃发生在任意时刻，都不会让同一次运行开始两次。
- **启动失败也记下来：** 文件夹不见了、模型角色被删了，这次就标为跳过并写明原因，下一次照常尝试。
- **自动保存：** 指定了"保存到"的自动化，任务完成（`completed`）后自动把产物保存过去。规则和手动保存一样：新建以任务命名的子文件夹，从不覆盖；保存记入任务日志。这是你设置自动化时为每次运行选好的位置，所以不再逐次确认。

## 存储

迁移 v3 新建 `automations` 表：`spec`（JSON）、`enabled`、`anchor`、`last_run`（JSON：计划时间、`started` 或 `skipped`、任务 id、原因）。自动化是配置，不是事件日志：它开始的每个任务才有自己的日志。

## 界面与命令

- **界面：**
  - 侧栏底部的"自动化"，可以新建、编辑、启用 / 暂停、立即运行、删除。
  - 每张卡片显示时间表、下次运行时间、上次运行结果，可以跳到对应任务。
  - 已完成的任务上有"定期运行…"，按这个任务预填一条新自动化。
  - 自动化开始的任务，标题下标着"来自自动化"。
- **命令行：** `warren automations` 列出全部，`warren automations run <id>` 立即运行一次。
