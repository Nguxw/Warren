# 000 理念

Warren 是一个常驻在个人电脑上的长程 Agent。它在后台接收任务，在隔离的工作区里长时间执行，只在需要你决定或者结果可以直接用的时候才打扰你。

它借鉴了 DeepSeek Super-Agent 原型的核心原则：**尽量少占用人的注意力，尽量多产出价值**。不同的是，原型面向团队和服务端，执行交给 DeepSeek Harness；Warren 面向个人和本地，执行运行时（Harness）是自己实现的。

## 本地长程带来的四个约束

| 约束 | 推出的设计 |
|---|---|
| 任务比进程活得久：会崩溃、休眠、重启 | 状态全部在磁盘上的事件日志里，进程不持有任何独有状态 |
| 任务比上下文窗口长 | 发给模型的上下文是日志的一个视图，而不是日志本身 |
| 任务比人的注意力长：无人值守 | 边界由机制保证（Grant、沙箱），不靠每一步审批；和人的沟通是异步的 |
| 跑在你的真实机器上 | 每个任务有自己的工作区；工具进程读不到密钥；Warren 不碰其他 Agent 的登录态 |

## 原则

- **日志是唯一事实来源。** 每个任务有一份只追加的事件日志。任务状态是对日志的折叠（fold），循环每一步都从状态推出下一步。崩溃恢复不是一段特殊代码，而是重新读日志。
- **边界靠机制，不靠提示词。** Grant 在任务创建时确定且不可变；需要更大权限就新建任务。提示词可以引导模型，但不能扩大它能碰的范围。
- **只用自己的凭证和目录。** Warren 的数据都在 `~/.warren/`（可用 `WARREN_HOME` 改），模型用你单独配置的 API key，GitHub 用单独的 token。它不读写 `~/.codex`、`~/.claude`、`gh` 等工具的配置和登录态。
- **只在值得的时候说话。** 一个任务只在三种情况下找你：需要回答问题、需要审批、结果已经可以用。其余时间安静地工作。
- **概念少。** 新需求优先变成已有概念的属性，而不是新概念。
- **扩展点先定接口，再按需实现。** 模型提供方、连接器、沙箱等都通过接口接入，每个接口先只做一个实现，并尽早用第二个实现验证接口设计。

## 概念

| 概念 | 含义 |
|---|---|
| Task | 一个工作单元，拥有自己的事件日志和工作区 |
| Event | 任务日志里的一条不可变记录 |
| Grant | 任务能碰什么：工作区、网络、可用的特权工具、预算。创建后不可变 |
| Trigger | 创建或唤醒任务的来源：手动、定时、GitHub 等连接器 |
| Attention | 等人处理的事：一个问题或一次审批 |

## 刻意不做的事

在日常使用中出现确实的需要之前，以下内容不做：多 Agent 协作、长期记忆、模型网关、网络白名单代理、每任务独立进程。架构保证它们以后可以加进来，而不需要改日志格式。
