# 006 界面与常驻

本文说明人如何使用 Warren：Web 界面、产物、设置、系统通知、开机常驻、单文件发布和桌面外壳。前置阅读：[003 运行时](003-runtime.md)、[005 安全边界](005-security.md)。

## 设计原则

界面遵循 [000](000-philosophy.md) 的"少占注意力"：

- **收件箱只按"需不需要你"排序：** 需要你处理 → 进行中 → 等待回复 → 已暂停 → 已结束。需要你处理的任务直接在列表里显示问题或待批准的动作。
- **系统通知只在两种时刻出现：** 任务需要你（提问或审批），以及任务完成或失败。进度不发通知。
- **界面上能做的事和 CLI 一样：** 新建任务、回答、批准或拒绝、发消息、暂停、继续、取消。界面和 CLI 都只是守护进程 API 的客户端。

## Web 界面

`apps/web`，React + TanStack Query，按组件拆分在 `src/components/`。

- **任务页的结构：**
  - **状态卡：** 显示"现在怎样、需要你做什么"。需要回答或批准时，直接在卡片里完成（回车提交）；运行中显示当前动作和已运行时长；结束后显示结论、发布的分支或 PR，以及改动摘要。
  - **标题下的信息：** 模型角色和实际回答的模型（例如 `main · gpt-6.1-terra`）、是否联网、用时、费用和调用次数。鼠标悬停在费用上，可以看到输入、缓存、输出和推理各用了多少 token。
  - **删除：** 标题栏的垃圾桶图标，或者鼠标移到侧栏任务上出现的删除按钮。删除前会确认，说明对话记录和工作区文件会被永久删除，已保存到别处的文件和推送过的分支不受影响；焦点落在"删除"按钮上，回车确认，Esc 取消。
  - **"动态"标签：** 时间线。模型的话作为正文；连续的工具调用折叠成一行摘要，例如"查看 3 处 · 修改 2 处 · 运行 1 条命令"，可以逐级展开到每次调用的参数和输出。每次模型调用如果有推理，显示一行"思考 · N tokens"。提供方给出推理摘要时，摘要显示在这一行下面；OpenAI 只对部分账户提供摘要，Warren 每次都会请求，拿不到时只显示用量。
  - **"改动"标签：** 工作区相对克隆起点的完整 diff，包括未提交的改动和新文件。
  - **"产物"标签：** 没有仓库的任务（调研、写报告），结果就是它写进工作区的文件，所以显示的是这些文件，不是 diff。见下文"产物"。
- **审阅 diff 也在沙箱里：** diff 由守护进程在**该任务的沙箱**里运行 git 生成，并关闭外部 diff 程序、textconv 和 fsmonitor。原因是工作区的 git 配置可以被模型改写，查看 diff 不能变成在沙箱外执行模型代码的入口。有测试在工作区里植入这些配置，确认它们没有被执行。
- **新建任务：** 打开就是起始页，正中是输入框，写完按回车就开始（⇧↩ 换行）。侧栏的"+"和 ⌘N 都回到这里，⌘K 聚焦侧栏搜索。
  - **默认值：** 一切都有默认值，只在需要时才改。默认不选文件夹（空工作区）、不预设保存位置、用"标准"模型，联网与否按设置。
  - **输入框下的一排按钮：**
    - **工作文件夹：** 点开可以选最近用过的、用系统的选择框挑，或者输入路径。git 仓库会被克隆，其他文件夹会被复制。
    - **保存到：** 上次用过的文件夹会列出来，但不会自动选中。
    - **模型：** 列出每档对应的模型名。
    - **联网：** 一个开关。
  - 下方有几条示例任务，点一下就填进输入框。
  - 任务页的追问框和回答框也是回车发送。
- **回车与输入法：** 所有回车发送的输入框都用 `keys.ts` 的同一个判断。中文、日文输入法用回车确认候选词，这个回车不能被当成发送，但各浏览器的事件顺序不同：
  - Chrome 会在这次按键上标记 `isComposing`；
  - WebKit（Safari，也是 macOS 桌面外壳用的内核）先结束组合，再派发 `isComposing` 为 false、keyCode 为 229 的按键。
  所以满足以下任一条件都算输入法的回车：事件标记了组合、keyCode 是 229、组合还没结束、组合结束不到 100 毫秒。
- **模型写的文字按 Markdown 显示：** 完成总结、模型回复、推理摘要、模型的提问和 Markdown 文件预览共用 `Markdown` 组件。
  - 支持 GFM（表格、任务列表、删除线）。还用 `remark-cjk-friendly` 修正了中文标点旁的加粗：`**看点：**AI` 在标准 CommonMark 里不算加粗，会原样显示星号。
  - 原始 HTML 不渲染，网页链接在外部打开，只加载网页图片。
  - 相对链接（如 `[报告](report.md)`）指向工作区的文件，点击后在"产物"页打开。
  - 你自己输入的文字保持原样，不当作 Markdown。
- **视觉：** 暖色纸感的中性色调，主色取自应用图标；颜色只用于有含义的地方，琥珀色表示"需要你"，绿色表示完成，红色表示失败。深浅色模式都单独调过配色。

- **打包：** 由 Bun 的 HTML import 直接打包（`import ui from "@warren/web/index.html"`），守护进程在 `/` 提供页面，不需要 Vite 等额外的构建工具。编译成单文件时界面也一并打包进去。
- **实时更新：** 页面订阅 `GET /events` 的 SSE 流，新事件直接追加到对应任务的时间线，列表和详情去抖后刷新。断线后由 EventSource 带上 `Last-Event-ID` 自动续传。
- **时间线即回放：** 时间线是事件日志的投影（`model.ts` 的 `timeline()`，纯函数，有测试）。回放滑块拖到第 N 步时，页面用 `@warren/core` 的 `foldEvents` 在浏览器里把日志折叠到那一步。看到的状态和守护进程重启时重建出的完全一致，因为用的是同一个函数。
- **中英双语，默认中文：** 界面文字都在 `i18n.ts` 的两份字典里，TypeScript 保证两份的键一一对应。语言和外观的选择记在浏览器的 localStorage 里，在设置页修改。时间线的提示由逻辑层输出为结构化数据（`Notice`），由界面按当前语言渲染。任务标题、模型回复、提问内容等用户数据保持原文。

## 产物

任务结束后，状态卡上有"打开 <主文件>"、"N 个文件"、"在访达中显示"和"保存到…"四个入口。保存过之后，最后一个按钮会变成"已保存到 <文件夹>"，点它会在访达中打开那个文件夹。复制文件夹的任务，产物页只列出它新增和修改的文件（带"新增"、"修改"标记），并说明有多少文件没动、删除了哪些。主文件按规则挑：工作区顶层的文档优先（Markdown、网页、PDF、文本），然后是数据文件（`primaryArtifact`）。

- **布局：** 预览占满整个宽度。预览顶部一行就是全部操作：
  - 左边是当前文件名；有多个文件时，点它会展开下拉列表。列表里顶层文件在前、主文件排第一，子文件夹（例如 `sources/` 里的原始证据）按文件夹分组，每项显示大小、时间以及新增 / 修改标记。版本库、依赖和缓存目录不列出。
  - 右边是"预览 / 源码"切换、复制路径（完整路径在提示里）和"在访达中显示"。
- **预览：**
  - Markdown 排版显示，支持表格（GFM），也可以切到源码；
  - 图片直接显示；
  - 其他文本按原样显示，超过 1 MB 只显示开头；
  - 二进制文件提示到访达中打开。
- **位置：** "在访达中显示"用 `open -R` 在访达中选中文件。还没有文件时，页面显示工作区的路径和同样的两个操作。
- **工作区由模型写入，所以读取时有防护：**
  - 列表不跟随符号链接；读取前把路径解析成真实路径，必须在工作区的真实路径之内，并且是普通文件。模型放一个指向 `~/.ssh` 的链接，守护进程也不会去读。
  - 内容以数据形式返回（文本，或 base64 编码的图片），不作为页面从守护进程的源提供。否则模型写的 HTML 或 SVG 会在界面的源里运行，拿到界面的 token。基于同样的原因，网页文件只显示源码，Markdown 里只加载 http(s) 图片，链接在新窗口打开。
  - "在访达中显示"只用 `open -R` 选中文件，从不用 `open` 打开它，所以模型写的 `.app` 或 `.command` 不会被运行。

## 设置

侧栏左下角的"设置"（⌘,）。修改会写回 `~/.warren/config.json` 和 `credentials.env`，大多数立即生效，不需要重启。

| 分组 | 内容 | 保存在哪 | 生效 |
|---|---|---|---|
| 通用 | 语言、外观（跟随系统 / 浅色 / 深色） | 浏览器 | 立即 |
| 通用 | 系统通知 | config.json | 立即 |
| 模型 | 每个角色的提供方、模型名、推理强度、接口地址、价格 | config.json | 下一次模型调用 |
| API 密钥 | OpenAI、Anthropic、GitHub 等密钥，也可以添加自定义名称 | credentials.env | 下一次调用 |
| 任务 | 新任务默认联网、同时运行的任务数、哪些操作需要批准 | config.json | 下一个任务或下一次调用 |

- **合并写入：** 修改先和文件里已有的内容合并，作为整体校验通过后才原子地写入。界面上没有的字段（GitHub、端口、模型的其他参数）原样保留。
- **立即生效：** 守护进程的各部分共用同一份配置和密钥对象，设置直接修改它们：
  - 模型客户端按"提供方 + 地址 + 密钥值"缓存，换了密钥自然用新客户端；
  - 审批规则在每次调用时读取；
  - 同时运行的任务数调大后，排队的任务马上开始。
  - GitHub 连接器、端口和沙箱是启动时装配的，改了要重启。
- **密钥只写不读：**
  - API 只接收密钥，返回的只有"是否已设置"和首尾几位（`sk-proj…cB8c`）；
  - 文件保持 0600，其他行（包括注释）原样保留；
  - 来自环境变量的密钥在界面里只读，因为每次启动时环境变量都会覆盖文件。

## 登录与本机安全

- **token：** API 的 token 保存在 `~/.warren/token`（0600），守护进程重启后不变；删除该文件即可轮换。`warren open` 用 `/#token=…` 打开页面，`#` 后面的片段浏览器不会发给服务器。页面读到 token 后存进本源的 localStorage，并清掉地址栏里的片段。
- **页面与 API 的权限：** 页面本身（HTML、JS、CSS）不含任何秘密，不需要 token；所有 API 都需要。
- **防 DNS 重绑定：** 守护进程只接受 Host 为 `127.0.0.1`、`localhost`、`[::1]` 的请求。恶意网页即使通过 DNS 重绑定把自己的域名解析到本机，请求带的也是它自己的域名，会被拒绝。

## 系统通知

`runtime/notifications.ts`：守护进程在提交事件后检查，遇到 `attention.requested` 或 `task.ended`（取消除外）时，通过 macOS 通知中心提醒你。

- 通知内容可能来自模型（比如它提的问题），所以文字作为 `osascript` 的参数传入，不拼进脚本文本，避免模型在可信进程里注入 AppleScript。
- 可以在配置中关闭：`"notifications": false`。

## 开机常驻

`warren service install` 会在 `~/Library/LaunchAgents/` 写入 launchd 用户代理（`dev.warren.daemon`），并立即加载：

- 登录时启动；退出后自动重启（`KeepAlive`，重启间隔 10 秒）。
- 运行的是和终端里一样的 `warren daemon`：有编译好的单文件程序时用它，否则用 bun 加源码。
- launchd 启动时几乎没有 `PATH`，所以 plist 里写入了 bun、Homebrew 和系统目录，任务才能找到 git 和 bun。
- 日志写到 `~/.warren/logs/daemon.log`。
- `warren service status` 查看状态，`warren service uninstall` 卸载。`WARREN_SERVICE_LABEL` 可以让开发实例和正式实例并存。

## 单文件发布

`bun run build` 输出 `dist/warren`。它是一个自带 Bun 运行时的可执行文件，包含 CLI、守护进程和打包好的界面，可以直接复制到 `PATH` 里使用。

## 桌面外壳

`apps/desktop`，Tauri v2（Rust）。它只是一层外壳，不含任何状态或逻辑；关掉它不会停止任何工作，因为工作在守护进程里。

- **窗口：** 加载守护进程提供的同一个页面。外壳读取 `~/.warren/daemon.json`（遵守 `WARREN_HOME`）拿到端口和 token，并确认端口能连通后，用 `/#token=…` 打开页面，和 `warren open` 一样。
- **守护进程未运行时：** 显示外壳自带的本地提示页（中英双语，默认中文），说明如何启动，并每 3 秒请求外壳重新连接，守护进程一起来就切换过去。
- **菜单栏：** 有一个模板图标，菜单里是"打开 Warren"和"退出（后台任务继续运行）"。关闭窗口只是隐藏；点击 Dock 图标会重新显示。退出外壳不影响守护进程里的任务。
- **链接：**
  - WebKit 视图默认会丢掉"新窗口"请求（`target="_blank"` 的链接），普通链接又会把整个界面换成那个网页。所以外壳检查每一次跳转：只有守护进程自己的地址（`127.0.0.1`，端口以 `daemon.json` 为准）和本地提示页留在窗口里，其他 http(s) 链接交给系统默认浏览器打开。
  - 链接来自模型写的文字，所以只放行 http 和 https，`file:`、`javascript:` 等协议一律不打开；网址作为参数传给 `/usr/bin/open`，从不拼进 shell 命令。
- **安全：** 守护进程的页面对外壳来说是远程来源，没有任何 IPC 权限，所以它在外壳里的能力和在浏览器里完全一样。只有外壳自己的本地提示页能调用唯一的命令 `connect`。本地页的内容安全策略禁止内联脚本。
- **构建：** `cd apps/desktop && bun run build` 输出 `src-tauri/target/release/bundle/macos/Warren.app`。需要 Rust 工具链（`brew install rustup && rustup default stable`）。
- **图标：** 源文件是 `apps/desktop/icon-src/` 里的 SVG，用 `bunx tauri icon` 生成各尺寸。菜单栏图标是单色模板图，会自动适配深色和浅色菜单栏。
